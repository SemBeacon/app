# SemBeacon app

Ionic 9 + Vue 3 (vue-facing-decorator) + Capacitor 8 app that scans for and advertises
SemBeacon / iBeacon / Eddystone beacons. Node >= 22, Yarn 1. See `README.md` for the full
development and testing guide.

## Commands
- `yarn install` (also copies OpenHPS bundles to `public/js/vendor`), `yarn dev` (https://localhost:8085)
- Before finishing any change: `yarn lint && yarn format:check && yarn typecheck && yarn test`
  (the same steps CI runs; `yarn format` and `yarn lint:fix` fix most findings)
- `yarn test:e2e` (Playwright), `yarn test:visual` (Docker only), `yarn test:native:android|ios` (Maestro)
- Details per test layer: skill `verify-changes`

## Architecture
Dependencies point one way: `views`/`components` -> `stores` -> `services`/`utils`.
Services and utilities never import stores, Vue or Ionic (enforced by `yarn lint`).
Platform differences go in `src/platform`; endpoints and keys in `src/config.ts` (`VITE_*` overrides).
Heavy beacon classification runs in `src/workers`.

## Code style that differs from Vue defaults
- Components are class-based (`vue-facing-decorator`, 38 files, no `<script setup>`);
  Pinia stores use the options syntax (`defineStore('id', { state, actions })`). Follow that,
  do not convert to Composition API, even if a generic Vue skill recommends it.
- Decorators and `emitDecoratorMetadata` are required (SWC via `unplugin-swc`, `reflect-metadata`
  imported first in `main.ts` and `tests/unit/setup.ts`). TypeScript is not `strict`.
- Prettier: 4 spaces, single quotes, trailing commas, 100 columns, LF.
- Import app code through the `@` alias (`@/stores/...`).

## Gotchas
- **OpenHPS is external.** `@openhps/*` and `@sembeacon/openhps` are not bundled: `yarn install`
  copies their browser builds to `public/js/vendor/openhps` (pruned and renamed by
  `scripts/process.js` using `scripts/externals_*.json`) and `vite.config.mts` maps the imports
  to those files. A new OpenHPS package needs entries in both places and in the Vite
  `external`/`paths` lists.
- **Do not minify the build** (`minify: false`): OpenHPS (de)serialization relies on class names.
- **Unit tests resolve ESM** (`mainFields` and `server.deps.inline` in `vitest.config.mts`) so that
  decorator metadata matches `@openhps/core`; a CJS import there breaks silently at runtime.
- The scanner worker `src/workers/BLEScannerWorker.worker.js` is plain JS, copied to
  `public/js/workers` by the Vite build; it cannot import app modules.
- `capacitor.config.ts` lists plugins per platform in `android.includePlugins` and
  `ios.includePlugins`. A new plugin must be added to each platform it supports, then `yarn sync`.
  Android advertising runs in a foreground service (`@capawesome-team/capacitor-android-foreground-service`).
- Services/utilities/`config.ts`/`demo/demoBeacons.ts` must not import `vue`, `pinia`, `@ionic/*`,
  stores or UI (ESLint `no-restricted-imports`).
- Ignored by ESLint: `android/`, `ios/`, `public/js`, `resources/`, `src/ontologies` (generated by
  `yarn ontologies`), `src/components.d.ts`.
- Visual baselines are valid only from the Playwright Docker image, whose tag is hard-coded in
  `.github/workflows/ci.yml` and must follow `@playwright/test` (skill `visual-baselines`).
- Demo mode (`VITE_DEMO_MODE=true`) is for tests and screenshots, never for releases.
- Dev server: https://localhost:8085 (self-signed certificate, `usePolling` for the devcontainer).

## CI
`ci.yml` (PRs and main): lint, format, typecheck, coverage, then Playwright e2e and visual in the
Playwright container. `native.yml` (main, nightly, manual): Maestro on Android emulator and iOS
simulator. `main.yml` (main): signed Android release APK from repository secrets.

## Conventions
- Match the surrounding code; Prettier config is `.prettierrc.js`, do not hand-format.
- Code, comments, tests and commit messages are in English. Commits use Conventional Commits
  (`feat:`, `fix:`, `test:`, `chore(deps):`, `docs:`).
- New logic gets a unit test in `tests/unit` mirroring the `src` path. Coverage thresholds in
  `vitest.config.mts` are a floor: raise them, never lower them.
- Browsers cannot scan or advertise BLE: the web build shows "not supported". Use demo mode
  (`SemBeacon.demo()` in the console, or `VITE_DEMO_MODE=true`) to get data.
- E2E tests must not use the network; fixtures live in `tests/e2e/fixtures/http`.
- Do not edit `android/` or `ios/` generated files by hand unless the change is native-only;
  run `yarn sync` after changing Capacitor plugins or `capacitor.config.ts`.
- Never commit secrets, keystores (`keystore/`) or signing passwords.

## Skills
Project skills live in `.agents/skills` (also reachable as `.claude/skills`):
- `verify-changes` - choose and run the right checks for a change
- `visual-baselines` - update Playwright screenshot baselines correctly (Docker only)
- `native-tests` - run and write Maestro flows on Android emulator / iOS simulator

Public skills, installed with `npx skills add` and pinned in `skills-lock.json`:
`vitest` (antfu/skills), `vue-testing-best-practices` and `vue-pinia-best-practices`
(vuejs-ai/skills), `ionic-vue` and `ionic-app-development` (capawesome-team/skills).
Where they recommend Composition API or `<script setup>`, this repo's class-component style wins.
